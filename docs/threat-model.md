## Known residual risks (be honest in the report)
- Demo auth (JWT, seeded users) is not production-grade identity: no MFA, no token revocation before expiry (8 h). Lockout is per email; the backend has no per-IP limit (Caddy adds one on the deployed instance: 20 sign-ins a minute per IP), so a known non-demo email can be locked out on purpose; the public demo accounts are exempt from the lockout in production (T12).
- Demo credentials are public by design: the seeded owner, accountant and viewer accounts share one published password (`seed/load.py`), and the deployed demo shows one-click sign-in so judges can try every role. This is acceptable only because of what those accounts can reach: every effect is sandbox-only (payments, emails and loan applications are rows in Sandbox* tables; nothing touches a real bank, inbox or lender), all data is fictional, and the daily AI budget (`DAILY_LLM_BUDGET_USD`, T10) caps what anyone can spend through the assistant, with per-user chat rate limits on top. What remains is vandalism of the demo state (approving or rejecting the planted actions); the demo reset restores it: owner-only `POST /demo/reset` (accountant/viewer → 403 + audited `demo_reset_forbidden`) and `python -m seed.reset` reload the golden data and append a `demo_reset` event; they never delete or rewrite AuditEvents, so `/audit/verify` still passes (`tests/test_demo_reset.py`); the reset also deletes the cached CFO memos (`test_demo_reset_clears_the_cached_memo`). Clearing Sandbox* rows happens only in `app/sandbox/reset.py`, called only by the reset. Chat conversations started before a reset are refused afterwards. On the deployed demo the reset also runs automatically every 3 hours (host cron, actor `scheduler:demo_reset`), and the login page says so. Never reuse this setup with real data or real integrations.
- LLM categorization can still mislabel; mitigated by confidence threshold + human review, not eliminated.
- Forecast is heuristic (historical behavior); not a guarantee.
- Audit chain: the hash is unkeyed, so someone able to drop the trigger (DB owner) can edit any event and recompute every later hash, or delete the newest events, and `/audit/verify` still passes. Mitigated in Phase 7: the evidence export (`python -m app.sandbox.evidence_export`) writes the latest seq + hash to `evidence/anchor.json`, committed to git; `--verify-anchor` detects any rewrite or truncation up to the anchored event. Events after the last export are protected only by the in-DB chain.
- `Policy.payee_allowlist_mode` is stored but not read: the gate always behaves as `strict` (only `is_allowed_payee` counterparties), which is the safe setting.
- PII masking (`agent/pii.py`) is regex-based and misses some formats: dashed account numbers (`000-123-456-789`), lowercase or dashed IBANs, fullwidth-@ and `[at]`/`[dot]` emails, phones like `555 0100 9999`, routing numbers with dashes. Zero-width-split numbers are caught (Cf characters are stripped first). Masking is a backstop: the agent never needs account details, payments use stored counterparty details only.
- Counterparty names, invoice numbers and SKUs reach the model and the reminder/terms templates unwrapped (not as `untrusted_text`). Today they come only from seed data, so they are not attacker-controlled; once invoice or counterparty upload exists they become an injection path and must be wrapped (model) and validated (templates).
- The agent's citation check covers money and percentages only; day/week counts and other bare numbers are not verified against records.
- Streamed chat text is shown before the citation and claim checks finish. The Phase 5 UI shows it only as a marked draft and replaces it with `done.message` (T13); a different client that renders the raw stream would not get this protection.
- The login page's one-click demo accounts read `DEMO_PASSWORD` from the frontend's environment and put it in the page; set it only on demo deployments (the seeded password is already public demo data).
- The categorizer can run on a cheaper model (`LLM_MODEL_CLASSIFIER`, e.g. Haiku); it may be less confident, which sends more transactions to the human review queue rather than mislabelling them (confidence < 0.7 → review).
- Financing catalog is simulated, not real offers. Every ranking carries a "not financial advice" disclaimer (`engine/financing.py`), shown under the Phase 6 comparison view as well; options are suggestions only and nothing executes without an approved Action.
