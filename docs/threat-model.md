# Threat model (living document → becomes security-assessment.md)

| # | Threat | Vector | Mitigation | Test | Status |
|---|---|---|---|---|---|
| T1 | Prompt injection via documents | Invoice notes / descriptions instruct agent to pay | Untrusted text wrapped as data; `schedule_payment` takes only counterparty id + payable invoice id (no payee name / bank details), pays stored details only; gate DENIES non-allowlisted payee, invoice not an open payable of that counterparty, or amount > invoice outstanding | A1 (incl. injection mapped onto QuickShip: $4,650 vs QS-2291 $465 → DENY); `test_gate.py`, `test_action_service.py`; `test_llm_classifier.py` | in progress — gate done (Phase 3): `policy/gate.py` DENIES non-counterparty/non-allowlisted payee, invoice not an open payable of that payee, amount > outstanding (bank + sandbox payments), and any extra param (`extra="forbid"`: no payee name, beneficiary or account field exists); every denial is an audited `denied` Action, never REQUIRE_APPROVAL. Reminder drafts are a fixed template over structured fields only (`services/drafts.py`), recipients are the stored `contact_email`. Agent side (notes as data) in Phase 4. Phase 1 categorizer: system prompt is a fixed constant; descriptions reach the LLM only as normalized `[A-Z0-9 ]` text inside a JSON array, reply is schema-constrained and re-validated, rules always win over the LLM; ingestion never creates counterparties from description text. Phase 2 engine: `engine/snapshot.py` never loads invoice `notes`, so forecast/what-if cannot be steered by them (`test_invoice_notes_never_affect_the_forecast`) |
| T2 | Agent executes without consent | LLM calls EXECUTE tool | EXECUTE only creates `proposed` Action; agent has no approve tool; human approval via authenticated API | `test_action_service.py`; Phase 4 tier tests | in progress — `services/action_service.py` is the only executor: EXECUTE tools become `proposed` Actions, run only after `approve` by an authorized human, gate re-checked at execution; agent actors carry the signed-in user's role (`agent:user:<id>`). Agent tool wiring in Phase 4 |
| T3 | Excessive payment | Agent or user requests large transfer | `max_single_payment` limit → DENY; amount ≤ invoice outstanding | A2 (`test_gate.py`, `test_action_service.py`) | mitigated — $9,000 → DENY (limit $5,000); amounts are strict integer cents > 0; two approved part-payments cannot exceed the invoice (re-check at execution) |
| T4 | Privilege escalation | Viewer/accountant approves restricted action | RBAC checks on every route + gate | A3 | planned |
| T5 | Duplicate execution | Retries / double clicks | Idempotency key, unique constraint | A4 (`test_action_service.py`) | mitigated — re-approve/re-execute of an executed Action returns its original result (audited `execute_replayed`); reused idempotency key returns the same Action; `sandbox_*.action_id` UNIQUE rejects a second write |
| T6 | Log tampering | DB edit to hide action | Hash-chained AuditEvent + verify; append-only in ORM and DB | A5 (`test_audit.py`) | mitigated — `hash = sha256(prev_hash + canonical_json(event))`; `verify_chain` reports the first broken seq for edited, re-hashed or deleted rows; migration 0003 trigger rejects UPDATE/DELETE on Postgres and SQLite; appends serialized with a Postgres advisory lock. Residual: see below (tail truncation) |
| T7 | Hallucinated numbers | LLM invents figures | All numbers from engine tools; citations required | Phase 4 smoke; `test_forecast.py` | in progress — every ForecastLine carries source_ids that resolve to real records (account/invoice/recurring_series/transaction); integer cents only; agent citations in Phase 4 |
| T8 | PII leakage to LLM | Account numbers/emails in prompts | `pii.py` masking before LLM calls | unit test | in progress — categorizer sends only normalized descriptions (card numbers, terminal IDs, phones, refs stripped) + direction, no amounts or DB ids (`test_llm_classifier.py`); agent `pii.py` in Phase 4 |
| T9 | Secret leakage | Keys in repo | `.env` gitignored; env-only config | CI grep check | in progress — `.env` gitignored, only `.env.example` committed |
| T10 | Abuse of chat endpoint | Spamming / cost | Rate limit per user | unit test | planned |
| T11 | Malicious upload | Huge / non-CSV file | Size + type limits, parser sandboxed from execution | `test_csv_parser.py` | in progress — parser enforces ≤2 MB, `.csv`, UTF-8, no NUL bytes, ≤20k rows, recognised header, all-or-nothing; stdlib `csv` only, nothing evaluated. HTTP upload route (with RBAC + audit) in Phase 3 |

## Known residual risks (be honest in the report)
- Demo auth (JWT, seeded users) is not production-grade identity.
- All seeded demo users share one known password (`seed/load.py`); demo data only.
- LLM categorization can still mislabel; mitigated by confidence threshold + human review, not eliminated.
- Forecast is heuristic (historical behavior); not a guarantee.
- Audit chain: someone able to drop the trigger (DB owner) can delete the newest events without breaking the chain; detecting that needs the latest hash anchored outside the DB (e.g. in the evidence export).
- Financing catalog is simulated, not real offers. Every ranking carries a "not financial advice" disclaimer (`engine/financing.py`); options are suggestions only and nothing executes without an approved Action.
